## 4. Evidence-trust audit (the "can we trust the JSONs?" question, answered in layers)

### 4.0 Model of the chain

```
OMNeT++ runs on Linux → .sca/.vec  →  rust-kpi-dashboard-0.2.1  →  run_rows.json
    →  config_summary.json  →  Figs/fig_01..09  →  chapters/5-chapter.tex tables/prose
```

A dashboard that "looks fine" is **not** independent confirmation of the JSONs — both are
outputs of the same parser. Independence has to come from re-derivation at each link:

### 4.1 Archive internal consistency — VERIFIED

- **Summaries are exactly the rows.** Recomputed all 1,755 numeric cells of the three
  `config_summary.json` files as arithmetic seed-means of `run_rows.json`: **0 drifts**.
- **Coverage:** 135 runs = 3 packages × 15 configs × exactly 3 seeds (`#0`–`#2`), no gaps.
- **Invariants on all 135 rows:** means and P95 within per-run [min,max]; reception counts
  within multicast fan-out bounds; per-AC drop attribution within the parser's 2×
  double-count guard; zero negative values.
- **Repeat ratios exact:** low = 250 logical × 3 copies = 750 physical; medium = 400 × 4 =
  1,600; high = 1,500 × 8 = 12,000 with 11,996–11,997 observed — 3–4 copies of the final
  sequence are cut by the t=60 s window edge. Matches `tab:impl:parameters` and the
  Evaluation burst profiles; an edge effect, not a defect.

### 4.2 Provenance & chronology — VERIFIED

- **Pin is real:** annotated tag `dissertation-2026-08` resolves to commit `da0d6162806…`
  and exists on `origin`; the local artifact clone sits clean at that exact commit;
  measurement-fix `5b0f584` is an ancestor (re-checked this scan).
- **Chronology is coherent:** uniform-load runs (Aug 15, 19:47–20:39) start ~4 min *after*
  the measurement-fix commit (19:43, UTC−3); archives built at 20:56/20:59 → JSON built
  *after* the runs it summarizes. Hotspot runs (Aug 16, 17:36–18:11) straddle the
  matrix-completion commit (17:49) — batch execution committing as it finished; all
  sources were committed the same evening. No run precedes the code it requires.

### 4.3 The one link not provable from this machine (residual risk, honestly stated)

not block the defense (the deposit is reproducible by construction), but it is the one
check still open. Closing checklist (30 min on the Linux machine):
